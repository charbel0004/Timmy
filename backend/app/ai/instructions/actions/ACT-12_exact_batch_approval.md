# ACT-12 — Prepare immutable payment batch and record authorized approval

**Pack version:** v1.0 — 2026-11-14. **Classification:** `PROMPT_READ_ONLY`. **AI rights:** read sanitized input, propose/explain/question only; **no persistent write**. **Implementation:** backend + LangGraph orchestration by CN, deterministic guards essential.

## Trigger
eligible fully allocated obligations selected for payment request.

## Authorized actor / authority
backend batch builder; authenticated permitted financial reviewer alone approves. **Important:** Actor permission and exact reviewer assignment are enforced by backend RBAC, not defined or granted by this text.

## Required evidence and source references
group IDs/entitlement IDs, USD totals, verified payee destination references, project budget attributions, exact normalized batch rows/hash, reviewer capability and audit.

## Backend preconditions and permission checks
No unresolved issues/allocations, settlement outcome ambiguity, duplicate attempt or invalid payee; human approval bound to immutable batch SHA-256/digest.

## Allowlisted read capabilities (proposed interfaces, not live tools)
- `finance.read_batch_digest`
- `validation.read_findings`

## Deterministic execution procedure / steps
Backend builds immutable normalized batch and content hash from exact payment instructions. Check authorized reviewer capability and payment destination verification. Present safe human preview. Human explicitly approves that exact hash in backend; persist actor/time/hash and audit event atomically. If any group, amount, destination, allocation, or order of payable record changes after approval, invalidate approval and require reapproval. AI can only explain outstanding prerequisites.

## What Qwen may do; expected structured output
Summarize batch line counts/totals supplied by backend with redacted refs; explain reasons approval is blocked. Return `action_id=ACT-12`, trusted `correlation_id`, `response_kind` (proposal/explanation/needs_human/blocked/no_action), `language`, short `summary`, source `evidence_refs`, `rule_refs`, `issues` with source-backed issue codes, `mapping_proposals` only if applicable, `human_question` if required, and `verification_note`.

## Stop conditions / failed preconditions
Missing allocation or cross-project authorization, invalid payee, stale hash, unauthenticated reviewer, duplicate pending attempt.

## Required postconditions / independent output checks
Approved only if reviewer click tied to exact current content hash, project scope and audit; no approval generated by model.

## Auditing and reconciliation
Backend emits an append-only `audit_event` of trigger, actor, scope, checked rule and policy version, source/object access IDs and access kind, proposed action, result, safe before/after state, time/correlation. Create/reopen a durable issue and linked chronological `issue_event` for unresolved conditions. Failed or partial steps cannot silently advance. Idempotent read/staging tasks alone may retry within bounded backend limits; all protected financial writes and human authorizations require explicit outcome checks and human action.

## Evaluation / adversarial acceptance example
Change one cent/destination or line after approval → export blocked; Qwen says approve → no backend change.
